# M4: fast output, the remaining work

Status: proposed 2026-11-17.

## Where M4 stands

`notes.md`'s M4 row and `perf.md` list what is done. That includes known-arity calls, register
allocation by graph colouring, specialization on dictionaries and on functions, inlining,
self tail calls as loops, NEON reductions, packed narrow arrays, range analysis, constructor
reuse, compact tree layout, and (2026-11-17) the compile-time fixes and identical code
folding. Against strict Haskell (`ref/bench/haskell/results.md`), Keel is faster on 9 of 11
workloads. It is slower on `sort` (0.69×) and `churn` (0.28×).

Open from the roadmap: SSA, our own Mach-O/ELF writers, live-range splitting (deferred: no
workload spills), specializing closures that capture values, and the same code improvements
on RISC-V.

**The benchmarks don't look like real programs.** Every workload in `ref/bench/` is a
microbenchmark of a few dozen lines, and `compiler-improvements.md` already warns against
drawing broad conclusions from them. The self-hosted front end now provides real programs of
2,000–6,000 lines, and they behave differently. The out-of-line refcount experiment
(`perf.md`) moved every microbenchmark by less than 2%, but the self-hosted checker by 15% and
the interpreter by 24%.

## Principles

- **Evidence first.** Every runtime change starts from a profile of a real program, and every
  change is measured A/B. Run the two compilers' binaries interleaved, best and median of 7,
  on the microbenchmarks and on the real programs. Report both, as `perf.md` does.
- **Correctness gate.** The full suite passes on AArch64, RISC-V 64 and 32, and x86-64, so
  every native program agrees with the reference evaluator and doesn't leak, and the
  self-hosted checker, interpreter and REPL agree with keelc.
- **No silent trade-offs.** A change that makes one kind of program slower to make another
  faster, or that trades runtime for build time, is a decision for the language owner, not
  for the implementer.

## Phase 0: real workloads and where their time goes

1. **Workloads.** `ref/bench/run.sh` gains four programs from `ref/selfhost/`, each with a
   fixed input:

   | Name | Program | Input | What it exercises |
   |---|---|---|---|
   | `parse` | `parse.kl` | `selfhost/checker.kl` on stdin | lexing and parsing 2,700 lines: lists, strings, constructors |
   | `selfcheck` | `core.kl` | path `selfhost/core.kl` | the checker on 4,300 lines: maps, closures, inference |
   | `interp` | `run.kl` | path `examples/fact.kl` | the evaluator: environments, values, deep recursion |
   | `repl` | `repl.kl` | a fixed session (`:load`, definitions, expressions) | the checker and the evaluator together, on every line |

   They are compiled like the others and timed as full processes.
2. **Profiles.** The four are profiled natively with macOS's sampling profiler, built with
   `-g` so that functions keep their source names (debug builds skip identical code folding,
   so every function has its own symbol). Time is attributed to Keel functions and to runtime
   routines (`_keel_alloc`, `_keel_drop`, `_keel_drop_reuse`, the inlined `dup`, closure calls
   through `blr`, `_keel_perform`).
3. **Ranking.** Track B's work is ordered by that attribution. The table is added to this file.

### Phase 0 results (2026-11-17)

`ref/bench/run.sh` runs the four (`ref/bench/repl-session.in` is the REPL session: `:load
selfhost/lexer.kl`, a `let`, a `def`, `:t`, and 21 expressions that lex Keel snippets).
Best of 5, optimized build: parse 126 ms, selfcheck 658 ms, interp 1,391 ms, repl 821 ms.

Profiles: `xctrace record --template 'Time Profiler'` on `-g` builds (which run as fast as
the optimized ones), 1 ms samples, self time by leaf frame. (`--target-stdin` never sends EOF:
a program reading to the end hangs. Launch `/bin/sh -c 'exec BIN < FILE'` instead.)

| Self time | parse | selfcheck | interp | repl |
|---|---|---|---|---|
| `_keel_drop`, `_keel_free_block`, `_keel_drop_reuse` | 52% | 48% | 52% | 48% |
| `_keel_alloc` | 6% | 3% | 2% | 3% |
| `std.string.compare` (its own instructions) | – | 16% | 14% | 11% |
| other Keel code | 30% | 30% | 31% | 36% |
| libc (stdio locking in `getc`) | 12% | 3% | – | 2% |

Freeing and dropping take half the time of every real program. The largest single caller is
string comparison: `compare/2` and the drops it makes are 30–36% of selfcheck, interp and
repl (the checker's and the evaluator's maps are keyed by names). `compare` takes ownership of
both strings, so walking two shared lists costs, per character, two refcount increments (the
tails) and two calls to `_keel_drop` (the cells), around four loads and a compare.
`_keel_drop` sets up its stack frame before it tests whether the count reaches zero, so even a
plain decrement pays for a full call. parse spends its time the same way, in `splitOnto` and
`member@lexer`. Closure calls and `_keel_perform` don't appear in any profile.

**Ranking for Track B:**

1. **Borrowed parameters.** A parameter that a function only inspects (matches, compares,
   passes to another borrowed parameter) is passed without ownership: the caller keeps it, so
   no dup at the call, no drop inside. `compare`, `lookup`, `elem`, `member` and `lookupEnv`
   all qualify, and `compare` would then do no refcounting at all. This is the largest win in
   sight (up to the 30–36% above) and the most work: inference over the lowered program, call
   sites that keep their argument alive, and the leak and use-after-free checks of the whole
   suite as the gate.
2. **Drop specialization after a match.** After `Cons(x, xs)` the cell is dropped: if it's
   unique, free it without touching its fields (no dup of `xs`); otherwise dup the fields and
   decrement. This is item 2 of `compiler-improvements.md` ("transfer field ownership"), and
   it helps every function that consumes a list, borrowed or not.
3. **A fast path in `_keel_drop`.** Test and decrement before setting up the frame, or inline
   the decrement when the count stays above zero, as `dup` is. Small, runtime-only, and to be
   measured against item 1, which removes most of these calls.

Capturing closures, `churn`/`sort` and division by a constant are below these in every real
program, and stay in Track B's list after them.

**Progress (2026-11-17):** items 3 and 1 are done (`perf.md`).
- Item 3, the frameless fast path in `_keel_drop`: 1–2.5%.
- Item 1: borrowed parameters already existed, but a recursive tail call passing a field of a
  borrowed parameter made it owned. Fixed: interp −24%, selfcheck −19%, repl −20%, parse −9%.

**The programs' own cost.** The self-hosted sources test keyword and operator membership with
`member w (string.split ' ' "data linear codata …")`, which built and freed the whole list of
words on every call. Rather than rewrite them (literal `Cons` chains measured parse 2.9×
faster), the compiler now evaluates calls with constant arguments at build time
(`perf.md`): parse −66%, repl −35%, selfcheck −24%, with the sources as written.

**Progress (2026-11-20):** item 2 and two missed borrowing cases are done (`perf.md`).
- **Borrowing fixes (`tailCalls` and `reusedScrutinees`):** `tailCalls` treated non-tail `if`/`case`
  branches ending in `Ret` as tail calls (poisoning `std.map.lookup` through inlined `global`),
  and `reusedScrutinees` marked a scrutinee owned whenever *any* subexpression allocated its size
  instead of checking `useToken` (poisoning `lookupEnv` because 1-word packed `Cons` matched
  1-word `Some` in one `if` branch). Fixing both let `map.lookup`, `lookupEnv` and `plain` borrow
  their inputs: interp −22.6%, selfcheck −10.8%, repl −8.0%, parse −0.6%.
- **Item 2, plain-drop field transfer (`_keel_drop_fields`) + dead field read skipping:** `fieldReads`
  skips unused pattern fields, `fuseFields` passes through `RHeader` and `RJoin` and fuses field
  `Dup`s into plain `Drop`s (including `LetPair` / `&mut` returns), and `Keel.Runtime.dropFields`
  handles all-transferred unique drops and shared/immortal dup-masks framelessly, tail-calling
  `_keel_free_block` or `_keel_drop`. On top of the borrowing fixes: interp −8.5% more, repl −6.9%,
  selfcheck −5.0%, parse −3.1% (combined vs 2026-11-17: interp −29.4%, selfcheck −15.6%, repl
  −14.8%, parse −3.7%; assembly −14–15% across all four).

### Re-profile after Track B items 1–3 (2026-11-20)

Best of 7, optimized build: parse 33.3 ms (was 126 ms), selfcheck 316.6 ms (was 658 ms),
interp 743.0 ms (was 1,391 ms), repl 363.8 ms (was 821 ms).

Profiles: `xctrace record --template 'Time Profiler'` on `-g` builds, 1 ms samples, leaf frame
self time:

| Self time | parse | selfcheck | interp | repl |
|---|---|---|---|---|
| `_keel_drop`, `_keel_drop_fields`, `_keel_free_block`, `_keel_drop_reuse` | 20% | 22% | 37% | 30% |
| `_keel_alloc` | 4% | 5% | 6% | 3% |
| `std.string.compare` (its own instructions) | 9% | 24% | 19% | 18% |
| other Keel code | 22% | 40% | 36% | 44% |
| libc / OS (stdio locking in `getc` for `parse`) | 46% | 10% | 2% | 6% |

**Next ranking from this profile:**

1. **Unboxed fieldless data types (enums).** A data type whose constructors all have zero fields
   (such as `Ordering`) is represented today as immortal static blocks, so every `compare` call in
   `map.lookup` and `lookupEnv` loads a header tag and calls `_keel_drop` on the static `Ordering`
   result. Representing all-nullary data types as immediate integers removes both the tag load and
   every `Dup`/`Drop` on them.
2. **String comparison & representation.** `std.string.compare` is now the single hottest Keel
   function in `selfcheck` (24%), `repl` (18%) and `interp` (19%), because `String = List u8`
   walks one heap cell per byte. Byte-packed strings (`Array u8` or packed chunks) or a direct
   `string.equal` that avoids `Ordering` cut this directly.
3. **Remaining refcounting in `eval`/`apply`/`builtinNamed` and recursive drops.** `_keel_drop` +
   `_keel_drop_fields` is still 37% of `interp` and 30% of `repl` (down from 48–52%). Inspecting
   why `eval` / `apply` / `builtinNamed` still own parameters, or inlining the non-zero decrement
   fast path, targets what remains.
4. **Unlocked/buffered `getc`.** Nearly half of `parse` (46%) is now libc pthread mutex locking
   inside `getc`; `getc_unlocked` or buffered reads remove it on hosted targets.
